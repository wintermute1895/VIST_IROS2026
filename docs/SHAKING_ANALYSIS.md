# VIST 机械臂抖动问题分析报告

## 问题现象

机械臂在使用VIST滤波器时出现剧烈抖动，表现为：
- 操作者输入与机械臂响应"打架"
- 需要用很大的力才能移动
- 运动不流畅，有明显的抵抗感

## 诊断数据

### 当前意图因子状态
```
data: [0.814, 0.295, 1.0, 0.0]
      [α,    α_geo, α_vel, α_alignment]
```

### 关键发现

1. **意图因子α过高**: 0.81-0.88
   - α接近1表示系统处于"精密约束模式"
   - 此时XY约束方差仅为0.01 rad² (约1.8°)

2. **几何因子异常**: α_geo = 0.295 (应该更高)
   - 距离感知工作不理想
   - 无法根据距离动态调整意图

3. **速度因子饱和**: α_vel = 1.0
   - 系统认为操作者"完全静止"或"完全对准"
   - 触发最强约束

4. **方向因子为0**: α_alignment = 0.0
   - 方向对齐检测失效

## 根本原因分析

### 1. 约束方差过紧 (主要原因)

**当前配置**:
```yaml
cons_variance_xyz: [0.01, 0.01, 1.0]  # XY约束方差
```

**问题**:
- 0.01 rad² ≈ 0.03 rad ≈ 1.8°
- 当α=0.88时，实际方差为:
  ```
  Σ = (1-α)·Σ_free + α·Σ_cons
  Σ = 0.12×1.0 + 0.88×0.01 = 0.129 rad²
  ```
- 这个方差太小，系统对操作者输入响应极其迟钝

**物理意义**:
- 方差越小 = 系统越"自信" = 越不信任人的输入
- 0.01的方差意味着系统只允许±1.8°的偏差
- 操作者任何超过这个范围的输入都会被强烈抵抗

### 2. 意图检测参数不合理

**当前配置**:
```yaml
w_geo: 0.5  # 几何权重
w_vel: 0.5  # 速度权重
intent_smoothing: 0.7  # 意图平滑
```

**问题**:
- w_geo和w_vel权重相等，但几何因子工作不理想
- 导致α值主要由速度因子主导
- 速度因子饱和(=1.0)导致α持续偏高

### 3. 频率不匹配 (次要原因)

**配置**:
```yaml
process_model:
  dt: 0.0125  # 80Hz
```

**实际运行**:
- 控制循环: 80Hz
- VIST内部dt: 可能使用了旧值0.02s (50Hz)
- 导致速度计算不准确

### 4. 意图平滑不足

**当前配置**:
```yaml
intent_smoothing: 0.7
```

**问题**:
- 0.7的平滑系数较低
- α值变化较快，容易产生突变
- 突变会导致控制指令跳变，引起抖动

## 修复方案

### 方案A: 放宽约束方差 (推荐，立即见效)

**修改**:
```yaml
cons_variance_xyz: [0.1, 0.1, 1.0]  # 从0.01增加到0.1
```

**效果**:
- 增加10倍，给操作者更多控制权
- 当α=0.88时，实际方差变为:
  ```
  Σ = 0.12×1.0 + 0.88×0.1 = 0.208 rad²
  ```
- 允许±8°的偏差，操作更流畅

**优点**:
- 立即见效
- 保持一定约束感
- 不改变意图检测逻辑

**缺点**:
- 约束感减弱
- 可能需要进一步调优

### 方案B: 调整意图权重 (治本)

**修改**:
```yaml
w_geo: 0.3  # 从0.5降低到0.3
w_vel: 0.7  # 从0.5增加到0.7
```

**效果**:
- 减少几何因子影响(因为它工作不理想)
- 增加速度因子影响，更跟随操作者
- α值会降低到0.5-0.7

**优点**:
- 从根本上降低α值
- 系统更跟随操作者意图

**缺点**:
- 需要配合方案A使用
- 可能需要多次调试

### 方案C: 增加意图平滑 (减少抖动)

**修改**:
```yaml
intent_smoothing: 0.9  # 从0.7增加到0.9
```

**效果**:
- α值变化更平滑
- 减少突变导致的抖动
- 响应稍慢但更稳定

**优点**:
- 直接减少抖动
- 不改变平均α值

**缺点**:
- 响应变慢
- 不解决根本问题

### 方案D: 修复频率不匹配

**修改**:
确保VIST内部使用正确的dt值

**效果**:
- 速度计算准确
- α_vel更合理

### 综合方案 (推荐)

**同时应用A+B+C**:
```yaml
# 方案A: 放宽约束
cons_variance_xyz: [0.1, 0.1, 1.0]

# 方案B: 调整权重
w_geo: 0.3
w_vel: 0.7

# 方案C: 增加平滑
intent_smoothing: 0.9
```

**预期效果**:
- α值从0.88降到0.5-0.7
- 实际方差从0.129增加到0.35-0.45
- 允许±11-12°的偏差
- 抖动显著减少
- 操作更流畅

## 理论背景

### VIST意图驱动方差调制

VIST的核心思想是根据操作者意图动态调整系统响应:

```
Σ(α) = (1-α)·Σ_free + α·Σ_cons
```

- **α=0**: 自由探索模式，Σ=Σ_free，系统完全跟随操作者
- **α=1**: 精密约束模式，Σ=Σ_cons，系统强烈约束到目标

### 方差的物理意义

方差 = 系统的"不确定性" = 对人类输入的"信任度"

- **大方差** (如1.0): 系统不确定，完全信任人的输入
- **小方差** (如0.01): 系统很确定，不信任人的输入

### 当前问题的本质

当α=0.88, Σ_cons=0.01时:
```
Σ = 0.12×1.0 + 0.88×0.01 = 0.129 rad²
```

系统认为:
- "我88%确定目标在这里"
- "我只允许±2°的偏差"
- "任何超过这个范围的输入都是错误的"

这导致系统与操作者"打架"。

### 修复的本质

通过增加Σ_cons到0.1:
```
Σ = 0.12×1.0 + 0.88×0.1 = 0.208 rad²
```

系统变为:
- "我88%确定目标在这里"
- "但我允许±8°的偏差"
- "给操作者更多控制权"
