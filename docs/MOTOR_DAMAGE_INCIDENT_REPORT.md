# J1电机损坏事故报告

**日期**: 2026-02-09
**受损部件**: J1 (Shoulder Roll) 电机
**严重程度**: 高（电机冒烟，需要维修/更换）

---

## 事故经过

### 时间线
1. **启动测试程序** - 运行 `python3 scripts/run_real_robot_vist_refactored.py`
2. **连接成功** - SDK连接到机器人
3. **执行enable_arm()** - 使能机械臂
4. **J1立即异常** - 在操作员开始操作之前
   - 过热
   - 异响
   - 冒烟
5. **紧急停止** - 操作员立即停止程序
6. **损坏确认** - 断电后手动转动J1，发现严重阻塞和异响

---

## 根本原因分析

### 主要原因：工具坐标系配置错误

**问题配置**：
- SDK配置了 `custom_gripper` 工具坐标系
- 偏移量：X=0.100m, Y=0.050m, Z=0.020m（10cm前向偏移）

**损坏机制**：
1. 当调用 `enable_arm()` 时，SDK使能电机
2. SDK认为末端应该在"夹爪中心"（手腕位置 + 10cm偏移）
3. 实际末端在"手腕位置"（无夹爪或夹爪未在工具坐标系中）
4. SDK立即命令J1移动来补偿这10cm偏移
5. J1被命令到不可达或极限位置
6. 电机卡死，持续尝试到达目标位置
7. 电流过大 → 过热 → 绕组短路或塑料件变形 → 冒烟

**为什么是J1而不是其他关节**：
- J1 (Shoulder Roll) 负责手臂的侧向摆动
- 10cm的前向偏移需要J1配合其他关节进行大幅度调整
- J1可能是第一个到达机械极限的关节

### 次要因素

1. **控制参数（已排除）**：
   - 速度/加速度参数在enable时不起作用
   - 控制频率在enable时不起作用
   - 这些参数只影响遥操作阶段

2. **关节偏移配置（已排除）**：
   - `joint_offsets[0] = -1.57` 用于对齐人体-机器人零位定义
   - 只在几何求解器中使用，Enable时几何求解器还未运行
   - 配置正确，不是导致损坏的原因

3. **符号翻转配置（已验证）**：
   - `joint_sign_flip` 配置与上次成功测试一致
   - 不是导致损坏的原因

## 损坏评估

### 症状
- **手动转动**：阻塞严重，需要较大力气
- **异响**：转动时有摩擦声或咔咔声
- **温度**：事故后电机温度异常高（烫手）
- **气味**：明显的烧焦味

### 可能的内部损坏
1. **齿轮箱损坏**：
   - 塑料齿轮因高温变形
   - 齿轮磨损或断裂
   - 齿轮箱内润滑脂失效

2. **轴承损坏**：
   - 轴承卡死或磨损
   - 轴承座因高温变形

3. **电机绕组**：
   - 绕组可能短路
   - 绝缘层可能损坏

### 维修建议
- **不要继续使用** - 可能导致更严重损坏
- **联系厂商** - 需要专业检修或更换
- **保留现场** - 不要拆解，保持保修资格

### 操作规程

#### 真机测试前必须检查：
1. **工具坐标系**：
   - 打开SDK Web界面
   - 确认当前使用 `Arm_Tip (0, 0, 0)`
   - 如果不是，点击"切换到此工具"

2. **机械臂姿态**：
   - 确认处于自然下垂或安全姿态
   - 确认无关节在极限位置
   - 确认无机械卡死

3. **电机健康**：
   - 确认所有电机冷却
   - 手动转动各关节，确认无阻塞
   - 确认无异响、无烧焦味

4. **配置参数**：
   - 控制频率 ≤ 15Hz
   - 电机速度 ≤ 0.3 rad/s
   - 电机加速度 ≤ 0.5 rad/s²

#### Enable流程：
1. 运行安全检查（自动）
2. 确认所有检查通过
3. 输入 'ENABLE' 使能
4. 观察10秒（自动倒计时）
5. 确认无异常
6. 等待倒计时后开始操作

## 经验教训

### 技术层面
1. **工具坐标系至关重要**：
   - 必须与实际硬件配置匹配
   - Enable时SDK会尝试补偿偏移
   - 错误配置可能导致硬件损坏

2. **Enable不是无害操作**：
   - Enable会立即通电并尝试保持/调整位置
   - 必须在enable前进行充分检查
   - 不能假设enable只是"打开电源"

3. **多层防护的必要性**：
   - 软件检查（安全检查系统）
   - 人工确认（多重确认机制）
   - 观察期（enable后倒计时）
   - 紧急停止（随时可按Ctrl+C）

### 流程层面
1. **配置变更需要验证**：
   - 任何配置修改都应该先在仿真中测试
   - 真机测试前应该review所有配置
   - 不确定的配置应该使用保守值

2. **渐进式测试**：
   - 第一次测试使用最保守参数
   - 确认安全后再逐步提高性能
   - 每次只改变一个参数

3. **文档和检查清单**：
   - 必须有明确的操作规程
   - 必须有检查清单
   - 必须有应急预案
