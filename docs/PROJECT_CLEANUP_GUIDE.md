# 项目清理指南

## 概述

`clean_project.py` 是一个安全的项目清理工具，用于删除调试过程中产生的临时文件和数据，为代码提交或归档做准备。

## 快速开始

### 1. 预览模式（推荐第一次使用）

```bash
python clean_project.py
```

这会显示所有将被删除的文件，但**不会实际删除**。

### 2. 实际删除

确认预览结果无误后：

```bash
python clean_project.py --delete
```

系统会要求你输入 `yes` 确认删除。

## 清理规则

### 会被删除的文件类型

| 类别 | 文件模式 | 说明 |
|------|---------|------|
| 🖼️ 可视化文件 | `*.png`, `*.jpg`, `*.gif`, `*.mp4`, `*.avi` | 调试图片和视频 |
| 📊 数据日志 | `*.npy`, `*.npz`, `*.csv`, `*.pkl` | 实验数据文件 |
| 🐍 Python 缓存 | `__pycache__`, `*.pyc` | Python 字节码缓存 |
| 📝 临时脚本 | `test_tmp_*.py`, `debug_*.py`, `temp_*.py` | 临时测试脚本 |
| 🗑️ 系统垃圾 | `.DS_Store`, `Thumbs.db` | 操作系统缓存 |
| 🧪 实验数据 | `data/experiments/*` | 实验记录目录 |

### 受保护的目录和文件

以下目录中的文件**不会被删除**：

- `docs/` - 文档和论文插图
- `assets/` - README 资源文件
- `config/` - 配置文件
- `weights/` - 模型权重
- `.git/` - Git 仓库
- `venv/`, `env/` - 虚拟环境

特殊保护的文件模式：
- `config/*.yaml` - 配置文件
- `weights/*.pth` - PyTorch 模型
- `docs/*.png` - 文档图片
- `assets/*.png` - 资源图片

## 自定义配置

如果需要调整清理规则，编辑 `clean_project.py` 顶部的配置区域：

```python
# 添加新的文件模式
PATTERNS_TO_DELETE = {
    'visualizations': ['*.png', '*.jpg', ...],
    # 添加你的规则
}

# 添加需要保护的目录
EXCLUDE_DIRS = {
    'assets', 'docs', 'my_important_folder'
}

# 添加需要保护的文件模式
PROTECTED_PATTERNS = [
    'important_data/*.csv',
]
```

## 使用场景

### 场景 1: 提交代码前清理

```bash
# 1. 预览要删除的文件
python clean_project.py

# 2. 检查列表，确保没有重要文件

# 3. 执行清理
python clean_project.py --delete

# 4. 提交代码
git add .
git commit -m "Clean up temporary files"
```

### 场景 2: 论文提交前瘦身

```bash
# 清理后项目大小通常从几百 MB 降到几 MB
python clean_project.py --delete

# 打包代码
tar -czf vist_code_submission.tar.gz \
    --exclude='.git' \
    --exclude='venv' \
    .
```

### 场景 3: 定期维护

建议每周运行一次，保持项目整洁：

```bash
# 每周五下班前
python clean_project.py --delete
```

## 安全机制

1. **默认 Dry Run**：第一次运行只显示，不删除
2. **用户确认**：删除前必须输入 `yes` 确认
3. **白名单保护**：重要目录和文件自动跳过
4. **详细日志**：显示每个被删除的文件
5. **错误处理**：删除失败会显示错误信息

## 常见问题

### Q: 我的某个 .png 文件很重要，怎么保护它？

A: 将它移到 `docs/` 或 `assets/` 目录，或者在 `PROTECTED_PATTERNS` 中添加规则。

### Q: 我想保留某些实验数据怎么办？

A: 在运行 `--delete` 前，先用 dry run 模式查看列表，然后将重要数据移到其他位置。

### Q: 误删了文件怎么办？

A: 如果文件在 Git 中，使用 `git checkout -- <file>` 恢复。如果不在 Git 中，无法恢复（这就是为什么要先 dry run）。

### Q: 能否只清理某一类文件？

A: 可以修改 `PATTERNS_TO_DELETE`，注释掉不想清理的类别。

## 最佳实践

1. **第一次使用前**：仔细阅读 dry run 输出，确认没有误伤
2. **定期清理**：不要等到项目几个 GB 才清理
3. **提交前清理**：保持 Git 仓库干净
4. **备份重要数据**：清理前确保重要实验数据已备份
5. **自定义规则**：根据项目特点调整配置
